# 人工复核模板（30 题）— 简历数字的前置关卡

> 用途：LLM judge 不进简历除非通过人工复核（提案 §7.3 / ADR-006）。
> 流程：从一次「真实 provider 运行」的 result 文件中，**逐条件分层抽样** 30 题
> （小数据集全量复核： judged < 30 时必须全判），按下表人工打分，算与
> judge 的一致率。**未完成复核前，该协议的 accuracy 不得写进 RESUME-READY.md。**

## 复核规则

| 人工打分 | 锚点 |
|---|---|
| 1.0 | 答案完整且与参考一致（数值/名称/方向全部对） |
| 0.5 | 部分正确（沾边但遗漏次要事实或表述偏差） |
| 0.0 | 错误 / 与参考矛盾 / 无中生有 / 拒答但参考有明确答案 |
| 弃判 | 参考可疑（数据集标注错误）→ 计入 `abstained`，不参与一致率 |

- 你看不到 judge 的分数再打分（先遮住 `judge` 列，全部打完再对答案防锚定）。
- 复核对象 = result 文件里的 `answer` 字段原文；同时核对原始 dataset 的
  `reference`。发现**judge 有系统偏向**（比如一律给 1.0）→ 记严重偏差，
  换 judge prompt 或模型重跑，而不是手工修分。

```markdown
## 一致性统计
- exact match（人工分 == judge 分）：__ / __ = ___%
- ±0.5 容忍：__ / __ = ___%
- 反转（人工=0 vs judge=1 或反之）：__ 题 → 严重偏差，必须修 judge 后重跑
- abstained：__ 题（参考可疑，出分母说明）

## 结论
- [ ] 复核通过：一致率 ≥ 80% 且反转 = 0 → 该 run 的 accuracy 可被引用
- [ ] 复核不通过（写明原因与重跑计划）
```
